```text
application
  入力を待つ

  選択IDに応じてゲームを進める

domain
  プレイヤー、メニュー、戦闘などのゲームルール

  メッセージ、シーン、選択肢、敵、スキルの定義

  同じゲーム状態をウィンドウへ描画する
```

## 4. 現在判明している不整合

自動テストは成功しているが、ゲーム全体の接続には次の問題がある。

### `run_game()`のシーン呼び出し

`application.py`にはシーン列を進める関数があるが、`run_game()`は存在しないCUI関数を呼んでいる。

```python
ui.play_scenes(ui, INTRO_SCENES)
```

アプリケーション自身の関数を呼ぶ形へ統一する必要がある。

```python
play_scenes(ui, INTRO_SCENES)
```

現在の関数名`play_scene()`は複数シーンを受け取るため、`play_scenes()`へ変更する。

### タイトル選択がCUI専用のまま

`run_game()`は次を呼んでいる。

```python
ui.select_title_menu()
```

選択待ちと検証はアプリケーション層へ移し、CUIは生の入力を返すだけにする。

### CUIの公開API不足

`application.py`が必要とする`receive_input()`が、`ui/cui/__init__.py`から公開されていない。

### `render_message()`の意味が混在

現在のCUIでは`render_message()`が完成済み文章を受け取るが、アプリケーションはメッセージキーを渡している箇所がある。

次の2責務へ明確に分ける。

- `_render_text(text, speed)`：CUI内部で完成済み文章を描画
- `render_message(message_key, **values)`：カタログから文章を取得して描画

### 結合テスト不足

個々の機能テストは成功しているが、本物のCUIを使用して`run_game()`を開始する結合経路が未検証である。
