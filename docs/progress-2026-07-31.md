# 魔法の塔 開発進捗と今後の計画

更新日：2026-07-31

## 1. 今回決めた方針

ミニゲームで試した次の責務分離を、RPG本編にも段階的に導入する。

```text
コンテキストデータ → GameState
ユーザーの選択     → Action
状態を変える処理   → ゲームルール
描画               → UI
進行管理           → Application
```

目的は、CUIと将来のGUIから同じゲームルールを利用できる構造にすることである。

メインループやUIに戦闘ルールを持たせず、次の流れを基本形とする。

```text
GameStateを描画する
  ↓
UIが入力を受け取る
  ↓
入力をActionへ変換する
  ↓
ゲームルールがGameStateを変更する
  ↓
終了していなければ繰り返す
```

## 5. 目標とする責務

### `domain`

- `GameState`、`Action`、`Player`、敵、戦闘などのゲーム概念
- HP、エネルギー、攻撃、勝敗などのルール
- `print()`、`input()`、`time.sleep()`を使用しない

### `data`

- シーン
- メッセージ
- メニュー
- 敵やスキルの初期定義

プレイ中に変化しない定義データを置く。

### `ui/cui`

- コンソールへの描画
- キーボード入力の取得
- 入力文字列からActionへの変換

ゲームのHPや階層を直接変更しない。

### `application.py`

- 描画、入力、Action処理を順番に呼び出す
- ゲーム全体のメインループを管理する

### `main.py`

- UIを選択してゲームを起動する
- ゲームルールを記述しない

## 6. 段階的な実装計画

### ステップ1：メニュー定義を正常な状態へ戻す

1. `MenuOption`と`MenuDefinition`の正式な配置を1か所に決める
2. 重複した定義を整理する
3. `label_key`、遷移先IDなどのフィールド名を統一する
4. `data/menus.py`のインポートを修正する
5. `tests/test_menu.py`を成功させる
6. 全既存テストを成功させる

完了条件：

- テスト収集エラーがなくなる
- タイトルメニューが開始と終了を保持する
- 型定義が重複していない

### ステップ2：タイトルメニューを新しい流れで動かす

1. 最小限の`GameState`を定義する
2. 開始と終了を表す`Action`を定義する
3. CUI入力をActionへ変換する
4. ActionによってGameStateを変更する
5. `application.py`から一連の処理を呼ぶ

完了条件：

- 開始と終了を選択できる
- 無効入力で状態が変化しない
- CUI以外に`input()`がない
- 状態変更処理に`print()`がない
- 自動テストと手動確認が成功する

### ステップ3：スライム1体との最小戦闘

1. `BattleState`と敵データを追加する
2. 通常攻撃Actionを追加する
3. プレイヤー攻撃と敵攻撃を実装する
4. HPが0になったときの勝敗を実装する
5. 固定乱数または乱数注入でテスト可能にする

完了条件：

- プレイヤーと敵が交互に行動する
- 敵を倒すと勝利する
- プレイヤーHPが0になると敗北する
- 戦闘ルールがCUIに依存しない

### ステップ4：エネルギーと「貯める」

1. プレイヤーの現在・最大エネルギーを扱う
2. `CHARGE` Actionを追加する
3. 通常攻撃との選択をメニュー化する
4. 上限を超えないことを確認する

### ステップ5：特殊攻撃をデータ化する

1. スキル名、威力、消費エネルギーを定義する
2. エネルギー不足を判定する
3. 特殊攻撃の成功と失敗を状態へ反映する
4. スキルを追加してもメインループを変更しない構造にする

### ステップ6：階層進行へ接続する

1. 戦闘勝利時に階層を更新する
2. 階層に応じた敵データを読み込む
3. 通常階とボス階を遷移させる
4. タイトルから戦闘、勝利、次階層までを1本につなぐ
