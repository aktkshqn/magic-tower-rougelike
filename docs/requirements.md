# 魔法の塔 要件定義書

## 1. 文書の目的

本書は、Pythonで制作する学習用テキスト型ローグライクRPG「魔法の塔」の第1版について、目的、遊び方、勝利・敗北条件、機能範囲を定義する。

開発は一度に完成させず、各ステップで次の順序を守る。

1. 今回作る機能の目的を確認する
2. 実装者がコードを書く
3. 自動テストと手動操作で確認する
4. AIによるコードレビューを受ける
5. 小改造課題を完了して次のステップへ進む

## 2. ゲーム概要

「魔法の塔」は、敵を倒しながら全5階の塔を登る、1人用のコンソールRPGである。

プレイヤーは通常攻撃、エネルギーを貯める行動、特殊攻撃を使って敵と交互に行動する。ターンを重ねてエネルギーを蓄積し、消費したエネルギーに応じて大きなダメージを与えることが戦闘の中心となる。敵を倒すと、その敵が持っていた特殊攻撃を奪い、その冒険だけの戦い方を組み立てる。5階のボス「塔の魔導王」を倒せば勝利となる。

冒険中に倒されると、その冒険で得た能力、特殊攻撃、その成長は失われ、1階から再挑戦する。ただし、最高到達階、累計撃破数、実績は保存される。

## 3. 想定プレイヤーと体験

- Pythonの基礎文法を理解し、ゲーム制作を通して設計とテストを学びたい開発者
- 1プレイ10～20分程度で、判断を伴うターン制戦闘を楽しみたいプレイヤー
- 敵から奪うスキルとランダムな成長によって、毎回少し違うビルドを試したいプレイヤー

提供する中心体験は次の3点とする。

- 限られたHPを守りながら、エネルギーを貯めて大技を放つ
- 通常攻撃を続けるか、攻撃を休んでエネルギーを早く貯めるか判断する
- 敵から奪った特殊攻撃を使い、ランダムな成長を楽しむ

## 4. 1プレイの流れ

1. 保存済みの進行記録を読み込む
2. 初期状態のプレイヤーで1階から冒険を始める
3. 階層の敵とターン制で戦う
4. 敵を倒したら撃破数と到達記録を更新する
5. 倒した敵が持っていた特殊攻撃を獲得する
6. スキルの所持上限に達している場合は、既存スキルと入れ替えて次の階へ進む
7. 1～4階では手順3～6を繰り返す
8. 5階で「塔の魔導王」と戦う
9. ボス撃破なら勝利、プレイヤーのHPが0なら敗北とする
10. 実績、最高到達階、累計撃破数を保存する
11. 結果を表示し、ゲームを終了する

## 5. 勝利・敗北条件

### 勝利条件

- 5階のボス「塔の魔導王」のHPを0にする

### 敗北条件

- いずれかの戦闘でプレイヤーのHPが0になる

### 敗北後の扱い

- 現在階、HP、エネルギー、冒険中に獲得・成長した特殊攻撃、冒険中撃破数をリセットする
- 最高到達階、累計撃破数、実績は維持する

## 6. 第1版の機能要件

### 6.1 プレイヤー

- 初期HPは30、最大エネルギーは10、攻撃力は5、防御力は2とする
- HPとエネルギーは0未満にならず、最大値を超えない
- 戦闘開始時のエネルギーは0とする
- 初期状態では「通常攻撃」と「貯める」を使用できる
- エネルギー不足の特殊攻撃は使用できず、ターンも消費しない

### 6.2 戦闘

- プレイヤーと敵が1回ずつ行動するターン制とする
- プレイヤーが先に行動する
- プレイヤーのターン開始時にエネルギーを1増やす
- 「貯める」を選ぶと、そのターンは攻撃せず、エネルギーを追加で2増やす
- プレイヤーの攻撃で敵を倒した場合、そのターンの敵行動は発生しない
- ダメージは `max(1, 攻撃値 - 防御値 + 乱数補正)` で求める
- 乱数補正は-1、0、1のいずれかとする
- 防御効果は、次に受ける1回の攻撃にだけ適用する
- 回復は最大HPを超えない
- 不正な入力では状態を変更せず、同じ行動選択を再表示する
- 任意の乱数シードを指定できるようにする

### 6.3 戦闘行動と特殊攻撃

| 行動 | 消費エネルギー | 効果 |
| --- | ---: | --- |
| 通常攻撃 | 0 | 基礎威力5で1回攻撃 |
| 貯める | 0 | 攻撃せず、エネルギーを追加で2増やす |
| 特殊攻撃 | スキルごとに設定 | エネルギーを消費して通常攻撃より大きなダメージを与える |

- 特殊攻撃の効果は、大きなダメージを与えることに限定する
- 属性、状態異常、回復、防御などの追加効果は特殊攻撃に持たせない
- 特殊攻撃ごとに名前、威力、消費エネルギー、最大威力を定義する
- 特殊攻撃が命中したとき、共通の成長率で成長判定を1回行う
- 成長に成功すると、その特殊攻撃の威力を1増やす
- 特殊攻撃の威力は、そのスキルに設定された最大威力を超えない
- 特殊攻撃で消費したエネルギーは、使用後に現在値から差し引く
- エネルギーは戦闘終了時に0へ戻す

### 6.4 スキル獲得

- 各敵は、奪うことのできる特殊攻撃を1個持つ
- 敵を倒すと、その敵が持っていた特殊攻撃を必ず獲得する
- 習得済みの特殊攻撃は重複して獲得しない
- 特殊攻撃は最大3個まで所持できる
- 所持上限に達している場合は、獲得する特殊攻撃と既存の特殊攻撃を入れ替えるか選ぶ
- 獲得を断った場合は、現在の特殊攻撃を維持する
- 奪った特殊攻撃の威力は初期値から始まる
- 冒険中に獲得・成長した特殊攻撃は、敗北または冒険終了時に失われる

### 6.5 階層と敵

| 階 | 敵 |
| ---: | --- |
| 1 | スライム |
| 2 | ゴブリン魔術師 |
| 3 | 石像の守護者 |
| 4 | 闇の騎士 |
| 5 | 塔の魔導王 |

- 階層が上がるほど、敵のHP、攻撃力、防御力を高くする
- 1～4階の敵は定義済み行動からランダムに行動する
- ボスは通常攻撃、強攻撃、自己回復の3行動を持つ
- 敵の数値は、戦闘処理を書き換えずに調整できるデータとして管理する

### 6.6 保存

- JSON形式で最高到達階、累計撃破数、実績を保存する
- 保存ファイルが存在しない場合は初期状態を使用する
- 保存項目が不足している場合は既定値で補う
- JSONが破損している場合はゲームを停止せず、初期状態を使用する
- 一時的な戦闘状態は保存しない

### 6.7 表示と操作

- 日本語のコンソール表示とキーボード入力を使用する
- 毎ターン、プレイヤーと敵のHP、プレイヤーの現在エネルギーと最大エネルギーを表示する
- 通常攻撃、貯める、使用可能な特殊攻撃と、その消費エネルギーを表示する
- 実行した行動、与えたダメージ、回復量、残りHPを戦闘ログに表示する
- 特殊攻撃が成長した場合は、成長前と成長後の威力を表示する
- 戦闘終了、階層到達、スキル獲得、スキル入れ替え、勝利、敗北を明示する

## 7. 非機能要件

- Python 3.12以降で動作する
- ゲーム本体はPython標準ライブラリだけで動作する
- 自動テストにはpytestを使用する
- ゲームロジックとコンソール入出力を分離する
- 固定シードを使ったテストで結果を再現できる
- AIサービスやネットワーク接続がなくてもプレイできる
- 保存データの異常によってゲーム全体が終了しない

## 8. 第1版の対象外

- 分岐マップ
- 武器、防具、アクセサリ
- 属性相性
- 毒、出血などの状態異常
- ショップ、通貨
- グラフィック、音声
- ネットワーク、ランキング、マルチプレイ
- 課金
- ゲーム実行中のAI文章生成
- AIによる敵の行動決定や勝敗判定

これらは第1版の完成後に、状態異常、装備、イベント、分岐マップの順で再検討する。

## 9. ステップ1の完了条件

- ゲームの目的を1文で説明できる
- 勝利条件と敗北条件を説明できる
- 1プレイの開始から終了までを順番に説明できる
- 第1版に含めるものと含めないものを区別できる
- 本書の内容に、実装前に解消すべき矛盾がない
