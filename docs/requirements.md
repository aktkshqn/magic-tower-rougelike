# 魔法の塔 要件定義書

## 1. 文書の目的

本書は、Pythonで制作する学習用テキスト型ローグライクRPG「魔法の塔」の第1版について、目的、遊び方、勝利・敗北条件、機能範囲を定義する。

開発は一度に完成させず、各ステップで次の順序を守る。

1. 今回作る機能の目的を確認する
2. 実装者がコードを書く
3. 自動テストと手動操作で確認する
4. AIによるコードレビューを受ける
5. 小改造課題を完了して次のステップへ進む

## 2. ゲーム概要

「魔法の塔」は、敵を倒しながら全5階の塔を登る、1人用のコンソールRPGである。

プレイヤーは通常攻撃と魔法スキルを使って敵と交互に行動する。敵を倒すたびにランダムに提示されるスキルから1つを選び、その冒険だけの戦い方を組み立てる。5階のボス「塔の魔導王」を倒せば勝利となる。

冒険中に倒されると、その冒険で得た能力とスキルは失われ、1階から再挑戦する。ただし、到達記録や実績で解放されたスキルは保存され、次回以降のスキル候補に追加される。

## 3. 想定プレイヤーと体験

- Pythonの基礎文法を理解し、ゲーム制作を通して設計とテストを学びたい開発者
- 1プレイ10～20分程度で、判断を伴うターン制戦闘を楽しみたいプレイヤー
- ランダムなスキル獲得によって、毎回少し違うビルドを試したいプレイヤー

提供する中心体験は次の3点とする。

- 限られたHPとMPを管理して敵を倒す
- 攻撃・防御・回復のどれを強化するか選ぶ
- 失敗を通じて新しいスキルを解放し、再挑戦する

## 4. 1プレイの流れ

1. 保存済みの進行記録を読み込む
2. 初期状態のプレイヤーで1階から冒険を始める
3. 階層の敵とターン制で戦う
4. 敵を倒したら撃破数と到達記録を更新する
5. 利用可能なスキルから最大3個をランダムに提示する
6. プレイヤーが1個を選び、次の階へ進む
7. 1～4階では手順3～6を繰り返す
8. 5階で「塔の魔導王」と戦う
9. ボス撃破なら勝利、プレイヤーのHPが0なら敗北とする
10. 実績、新規解放スキル、最高到達階、累計撃破数を保存する
11. 結果を表示し、ゲームを終了する

## 5. 勝利・敗北条件

### 勝利条件

- 5階のボス「塔の魔導王」のHPを0にする

### 敗北条件

- いずれかの戦闘でプレイヤーのHPが0になる

### 敗北後の扱い

- 現在階、HP、MP、冒険中に習得したスキル、冒険中撃破数をリセットする
- 最高到達階、累計撃破数、実績、解放済みスキルは維持する
- 初回敗北時に「生命吸収」を解放する

## 6. 第1版の機能要件

### 6.1 プレイヤー

- 初期HPは30、最大MPは10、攻撃力は5、防御力は2とする
- HPとMPは0未満にならず、最大値を超えない
- 戦闘開始時にMPを最大まで回復する
- 通常攻撃、強打、魔法障壁、治癒を初期状態で使用できる
- MP不足のスキルは使用できず、ターンも消費しない

### 6.2 戦闘

- プレイヤーと敵が1回ずつ行動するターン制とする
- プレイヤーが先に行動する
- プレイヤーの攻撃で敵を倒した場合、そのターンの敵行動は発生しない
- ダメージは `max(1, 攻撃値 - 防御値 + 乱数補正)` で求める
- 乱数補正は-1、0、1のいずれかとする
- 防御効果は、次に受ける1回の攻撃にだけ適用する
- 回復は最大HPを超えない
- 不正な入力では状態を変更せず、同じ行動選択を再表示する
- 任意の乱数シードを指定できるようにする

### 6.3 スキル

| スキル | MP | 効果 |
| --- | ---: | --- |
| 通常攻撃 | 0 | 基礎威力5で1回攻撃 |
| 強打 | 3 | 基礎威力9で1回攻撃 |
| 魔法障壁 | 2 | 次に受けるダメージを5軽減 |
| 治癒 | 4 | HPを8回復 |
| 連撃 | 4 | 基礎威力4で2回攻撃 |
| 瞑想 | 0 | MPを4回復 |
| 生命吸収 | 5 | 基礎威力6で攻撃し、HPを3回復 |

- 敵撃破後、習得可能なスキルをランダムに最大3個提示する
- 習得済みスキルと未解放スキルは候補に含めない
- 候補が3個未満の場合は、残っている候補だけを表示する
- 候補がない場合は、選択画面を出さず次の階へ進む

### 6.4 スキル解放

- 3階へ到達すると「連撃」を解放する
- 1回の冒険で3体を倒すと「瞑想」を解放する
- 初めて敗北すると「生命吸収」を解放する
- 解放済みスキルを重複登録しない
- 解放状態は次回起動時にも維持する

### 6.5 階層と敵

| 階 | 敵 |
| ---: | --- |
| 1 | スライム |
| 2 | ゴブリン魔術師 |
| 3 | 石像の守護者 |
| 4 | 闇の騎士 |
| 5 | 塔の魔導王 |

- 階層が上がるほど、敵のHP、攻撃力、防御力を高くする
- 1～4階の敵は定義済み行動からランダムに行動する
- ボスは通常攻撃、強攻撃、自己回復の3行動を持つ
- 敵の数値は、戦闘処理を書き換えずに調整できるデータとして管理する

### 6.6 保存

- JSON形式で最高到達階、累計撃破数、実績、解放済みスキルを保存する
- 保存ファイルが存在しない場合は初期状態を使用する
- 保存項目が不足している場合は既定値で補う
- JSONが破損している場合はゲームを停止せず、初期状態を使用する
- 一時的な戦闘状態は保存しない

### 6.7 表示と操作

- 日本語のコンソール表示とキーボード入力を使用する
- 毎ターン、プレイヤーと敵のHP、プレイヤーのMPを表示する
- 選択可能な行動とMP消費量を表示する
- 実行した行動、与えたダメージ、回復量、残りHPを戦闘ログに表示する
- 戦闘終了、階層到達、スキル習得、スキル解放、勝利、敗北を明示する

## 7. 非機能要件

- Python 3.12以降で動作する
- ゲーム本体はPython標準ライブラリだけで動作する
- 自動テストにはpytestを使用する
- ゲームロジックとコンソール入出力を分離する
- 固定シードを使ったテストで結果を再現できる
- AIサービスやネットワーク接続がなくてもプレイできる
- 保存データの異常によってゲーム全体が終了しない

## 8. 第1版の対象外

- 分岐マップ
- 武器、防具、アクセサリ
- 属性相性
- 毒、出血などの状態異常
- ショップ、通貨
- グラフィック、音声
- ネットワーク、ランキング、マルチプレイ
- 課金
- ゲーム実行中のAI文章生成
- AIによる敵の行動決定や勝敗判定

これらは第1版の完成後に、状態異常、装備、イベント、分岐マップの順で再検討する。

## 9. ステップ1の完了条件

- ゲームの目的を1文で説明できる
- 勝利条件と敗北条件を説明できる
- 1プレイの開始から終了までを順番に説明できる
- 第1版に含めるものと含めないものを区別できる
- 本書の内容に、実装前に解消すべき矛盾がない
